# 探索地点布局与 UI 改造计划

## 目标与范围

将本轮确认的设计稿落实到 `/locations`。采用温暖琥珀风格、四色活动入口、照片内标题和白色圆角地点卡片，压缩查找区并优化兴趣选择。

设计参考位于独立项目 `gomate-40fb`。正式实现复用仓库组件、语义 token 和真实 API 数据。交付范围为探索地点页面及其专用组件、中英文文案、直接相关测试与现行文档。

## 实现决策

- 调整 Hero 留白、宽度与结果区对齐，保留原有四色场景入口和图片叠字卡片。
- 兴趣采用轻量浅底圆角标签，桌面连续排列，手机完整换行。全部兴趣入口使用明确的展开控件，所有标签均可访问。
- 全部兴趣面板复用现有 Modal 与焦点管理机制，支持暂存、取消和应用。快捷标签即时应用，兴趣内部 OR、其他维度 AND。
- 复用现有服务器搜索、分页、URL 与返回恢复合同。设计稿中的跨简介、城市、标签本地搜索是演示能力，正式版本沿用现有服务端搜索合同。
- 面板的应用按钮使用“应用筛选”。当前分页 DTO 无法仅凭已加载的 12 条结果准确计算任意草稿条件的总数。
- 所有可见文本与可访问名称走中英文 i18n。主题、44px 触控目标、键盘、减少动态效果遵循现行规范。
- 使用真实地点封面和现有数据。生产数据、权限、API、数据库、全局导航与其他页面属于本次范围之外。

## 验证策略

先扩展现有地点组件和浏览器测试，验证新布局与兴趣面板的回归，再实施对应改动。重点覆盖真实组件入口、搜索与筛选组合、URL 恢复、慢请求、空态、失败和返回位置。

使用仓库规定的 pnpm 与 Node。完成 i18n:build、i18n:validate、lint、type-check、test、build，以及适用的完整验证门禁。浏览器检查 320/390/768/1440px，中英文、亮暗主题、键盘与 reduced-motion。模拟视口与真机验收分别记录。

## 交付

实现完成后读取 REVIEW.md，交由独立上下文子代理审查。明确问题修复并复审后按模板创建中文 PR。合并依据当前 PR head 的审查、必需 CI 和仓库保护规则决定。发布验证依据受保护流程的实际结果记录。

本计划为执行中的工作材料。完成后把稳定行为同步到现行文档，并按仓库规范将一次性计划归入 Git 历史。

## 风险

- 原型与正式组件的样式层叠不同，需在真实应用里测量布局，不能用原型截图替代验收。
- 弹层关闭、条件刷新和语言切换可能影响焦点，需验证关闭后焦点以及旧请求取消。
- 窄屏长标签、长城市名称与英文增长可能撑宽布局，需覆盖完整文本、换行和操作可达性。
- 原型真实数量预览依赖全量本地数据，正式 UI 应避免展示未经服务器确认的草稿数量。

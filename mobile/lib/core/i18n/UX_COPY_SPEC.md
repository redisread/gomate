# GoMate UX 文案 + 情感设计规范

> 移动端短文案体系，核心目标：让用户感到被理解、被支持、被陪伴。

---

## 1. 产品声音（Brand Voice）

### 人格特质（5 个关键词）

| 关键词 | 说明 |
|---|---|
| **温暖** | 像一个真正关心你的朋友，不是冷冰冰的工具 |
| **聪明** | 懂你说的话，不需要格式化输入 |
| **轻盈** | 不给人压力，轻松自然 |
| **可靠** | 说到做到，不会丢失你托付的事情 |
| **有趣** | 偶尔一点小幽默，但不刻意 |

### 整体感知

> 像一个聪明、温柔、随叫随到的朋友——不评判你，不催促你，只是帮你把事情变得简单一点。

### 语言风格原则

**用词偏好**
- 简短优先，能用 5 字表达就不用 10 字
- 用口语化动词：「搞定」「加进去」「说说」「试一次」
- 避免技术术语：不用「操作」「执行」「提交」「处理中」
- 适量使用 emoji，只在庆祝、鼓励时出现，不滥用

**语气**
- 亲切，像朋友说话，不像产品文档
- 第二人称「你」，不用「用户」「您」
- 允许使用「吧」「呢」「哦」等语气词，增加温度
- 带问号的句子让用户感到被询问，不是被命令

**禁用词/句式**

| 禁用（工具感） | 替换（温暖感） |
|---|---|
| 操作已完成 | 搞定啦 ✓ |
| 请输入内容 | 说说你在想什么？ |
| 提交失败，请重试 | 这次没成功，再试一次？ |
| 系统错误 | 服务器有点小问题，稍后再来？ |
| 无数据 | 这里还空空的 |
| 点击确认 | 好，就这样 |
| 密码不符合规则 | 密码至少需要 8 位，安全感更强一点 |
| 您的账户 | 你的账号 |
| 功能异常 | 这个功能出了点小状况 |

- 密码错误：`邮箱或密码不对，再试一次？`

| 场景 | 主文案 | 副文案 |

`添加任务` / `今天计划` / `回顾昨天` / `头脑风暴` / `设个提醒` / `规划这周`

## 9. 情感设计原则（5 条）

### 原则 1：说人话，不说机器话

**说明：** 所有文案使用真实对话语气，避免任何「操作成功」「请输入」「提交中」类机器语言。

**Before / After：**
- ❌ `数据加载中，请稍候` → ✅ `加载中…`
- ❌ `操作已完成` → ✅ `搞定啦 ✓`
- ❌ `请输入任务标题` → ✅ `这件事叫什么？`

**Flutter 实现提示：**
- 所有 `CircularProgressIndicator` 配合 `Text('加载中…')` 或 `Text('想一想…')` 使用
- 使用 `AnimatedSwitcher` 在思考状态和完成状态之间切换，让文案转变有动效

---

### 原则 2：成功时给庆祝，失败时给安慰

**说明：** 完成重要操作时用 emoji 和语气词表达喜悦；出错时不责怪用户，提供再试的勇气。

**Before / After：**
- ❌ `任务创建成功` → ✅ `加进去了 ✓`
- ❌ `网络请求失败` → ✅ `这次没成功，再试一次？`
- ❌ `全部任务已完成` → ✅ `今天的事全部搞定了 🎉`

**Flutter 实现提示：**
- 成功 Toast：使用 `ScaleTransition` + `FadeTransition` 进场，配合轻微振动反馈（HapticFeedback.lightImpact）
- 完成任务：卡片使用划过动效（`SlideTransition`），消失前短暂放大（scale: 1.05 → 0）

---

### 原则 3：空状态是邀请，不是报错

**说明：** 空状态页不应让用户感到迷失，而是温柔邀请用户创建第一条内容。

**Before / After：**
- ❌ `暂无数据` → ✅ `这里还空空的，把脑子里的事说出来`
- ❌ `您还没有创建任何任务` → ✅ `今天什么都没有安排，尽情享受，或者计划点什么？`

**Flutter 实现提示：**
- 空状态配合轻微的 Lottie 动画（如浮动的云朵/星星），不使用静态图标
- 按钮使用 `ElevatedButton` 并加 `pulse` 动效吸引注意力

---

### 原则 4：时间感知，让问候有温度

**说明：** 根据当前时间动态调整问候语，让用户感到 App 知道他们在哪个时刻。

**Before / After：**
- ❌ `你好` → ✅ `早上好，新的一天从这里开始 ☀️`（早上）
- ❌ `欢迎使用` → ✅ `还没休息？注意身体哦 🌟`（深夜）

**Flutter 实现提示：**
```dart
String getGreeting() {
  final hour = DateTime.now().hour;
  if (hour >= 6 && hour < 12) return AppStrings.greetingMorning;
  if (hour >= 12 && hour < 17) return AppStrings.greetingAfternoon;
  if (hour >= 17 && hour < 20) return AppStrings.greetingEvening;
  if (hour >= 20 && hour < 23) return AppStrings.greetingNight;
  return AppStrings.greetingLateNight;
}
```
- 问候语每次进入主页时用 `FadeIn` 动效出现，不要突兀刷新

---

### 原则 5：危险操作要「软化」，不要「恐吓」

**说明：** 删除/清空等危险操作的确认弹窗，语气应当平静而温和，给用户选择的空间而非制造恐惧。

**Before / After：**
- ❌ `此操作不可逆，确认删除？` → ✅ `删掉之后就找不回来了哦`
- ❌ `取消` → ✅ `先不了`（保持轻松语气）
- ❌ `确定` → ✅ `删掉吧`（语气温和而非强制）

**Flutter 实现提示：**
- 使用 `showModalBottomSheet` 代替 `AlertDialog`，视觉上更轻柔
- 危险按钮（删除）使用 `TextButton` 而非 `ElevatedButton`，降低视觉压迫感
- 取消按钮始终在上方或更显眼的位置，给用户逃生出口

## 文案 Dart 常量文件

完整实现见：`lib/core/i18n/app_strings.dart`

该文件：
- 所有文案以 `static const String` 定义，保证编译期类型安全
- 每个常量均有 `/// @tag` 注释，预留 ARB 国际化格式扩展
- 动态参数用 `{placeholder}` 格式标注，运行时通过 `replaceAll('{name}', value)` 注入
- 按功能域分块，方便查找和维护

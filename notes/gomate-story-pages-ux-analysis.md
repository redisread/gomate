# gomate 故事详情页 / 编辑页 UI/UX 问题分析

> 请求：@Victor 2026-07-18
> 分析者：@Steven
> 范围：`/discover/[id]`（故事详情）、`/discover/[id]/edit`（故事编辑）、`/discover/create`（发布故事）

---

## 一、核心结论

这两页**不是「功能缺失」，而是「设计语言不统一」**。详情页用的是 GoMate Design System v2.0 的 token（`--background` / `--foreground` / `--primary` / `--border` / `rounded-lg`），而编辑页仍在用早期遗留的「琥珀渐变 + 圆角大卡片」视觉（`bg-gradient-to-b from-amber-50/30`、`rounded-xl`、`bg-amber-500`）。用户从详情页点「编辑」会明显感到跳到了另一个产品。

发布页（create）又介于两者之间：部分使用 DS token，部分使用 amber 自定义样式。三个页面三种气质。

---

## 二、故事详情页 `/discover/[id]` 问题

### 2.1 设计系统执行不彻底

- **背景不统一**：`bg-background` 与 gomate 其他页面的 `--bg` `#FAF7F2` 可能有轻微偏差，需要确认 `bg-background` 是否映射到 DS v2.0 的 `--bg`。
- **Eyebrow 标签样式过重**：`rounded-full border border-primary/20 bg-primary/10` 是一个彩色 pill，在 DS v2.0 中应该更克制（参考 `/locations` 的标签用法）。
- **Byline 区域信息密度过高**：把「发布日期、浏览量、点赞数、阅读时长、字数」全部塞进一行，阅读故事前用户不需要这么多 metrics。建议只保留「作者 + 日期 + 阅读时长」，浏览量/点赞数移到文章底部操作区。

### 2.2 排版问题

- **标题过大**：`text-3xl sm:text-4xl lg:text-5xl` 在 `max-w-3xl` 容器中显得拥挤。故事不是新闻 headline，建议 `text-2xl sm:text-3xl` 更克制。
- **摘要样式与正文区分度不足**：`border-l-2 border-primary/50 pl-4` 像引用块，但摘要不是引用。建议改为普通灰色文字或引言样式。
- **正文容器与封面容器宽度不一致**：正文 `max-w-3xl`，封面 `max-w-5xl`，视觉跳跃。建议统一为 `max-w-3xl` 或封面改为 `max-w-4xl` 居中。

### 2.3 交互问题

- **点赞按钮位置靠后**：点赞是主要互动，却放在文章最底部。用户读完长文后可能直接离开。建议在 byline 区域或文章顶部提供轻量点赞入口，底部保留完整操作区。
- **删除按钮与编辑按钮并列**：删除是危险操作，视觉上与编辑按钮权重相同，容易误触。建议删除按钮更弱（文字链接或放在「更多」菜单里）。
- **分享按钮有两个入口**：顶部一个 + 底部 StoryActions 一个，重复。建议只保留底部一个。

### 2.4 a11y / 工程问题

- `StoryDetail` 是 `client:visible` 加载的 React island，SEO 虽然通过 SSR 的 `storyData` 解决，但**无 JS 用户看不到任何内容**（骨架屏也没有）。可以考虑 SSR 渲染核心内容，JS 只增强交互。
- `story.location?.name` 在 eyebrow 和正文底部重复出现，可以合并。

## 三、故事编辑页 `/discover/[id]/edit` 问题

### 3.1 设计语言与详情页断裂（最严重）

| 元素   | 详情页                 | 编辑页                                       | 问题             |
| ------ | ---------------------- | -------------------------------------------- | ---------------- |
| 背景   | `bg-background`        | `bg-gradient-to-b from-amber-50/30 to-white` | 渐变背景是旧视觉 |
| 强调色 | `--primary`（DS 琥珀） | `bg-amber-500` / `text-amber-600`            | 色值不一致       |
| 圆角   | `rounded-lg`           | `rounded-xl`                                 | 不一致           |
| 按钮   | DS secondary/primary   | `bg-amber-500 text-white`                    | 不一致           |
| 标签   | DS pill                | `rounded-full bg-amber-500`                  | 不一致           |
| 输入框 | DS form                | `rounded-xl border focus:ring-amber-200`     | 不一致           |

**建议**：编辑页全面接入 DS v2.0 token，与详情页保持一致。

### 3.2 布局问题

- **桌面端左右分栏过宽**：`lg:grid-cols-12` 左 4 右 8，编辑器区域过大，表单区域过挤。建议改为 `lg:grid-cols-3`（左 1 右 2）或上下结构。
- **编辑器高度固定**：`height: calc(100vh - 7rem)` 在小屏或窗口缩放时可能溢出。建议最小高度 + 自适应。
- **移动端体验差**：左右分栏在移动端变成上下堆叠，但表单字段很多，用户要滚很久才能到编辑器。建议移动端把「标题/摘要/封面/地点/标签」做成可折叠的「基本信息」面板，默认展开标题和摘要。

### 3.3 交互问题

- **保存按钮在 header**：用户编辑长文时需要滚到顶部才能保存。建议编辑器右下角增加浮动保存按钮，或 header 保持 sticky（已 sticky，但视觉上不明显）。
- **未保存提示不明显**：`text-xs text-amber-600 hidden sm:inline` 在移动端直接隐藏，用户不知道有未保存修改。建议改为保存按钮上的红点或按钮文字变化。
- **草稿恢复横幅突兀**：`bg-amber-50` 横幅在页面顶部，与整体视觉冲突。建议改为更克制的顶部通知条。
- **标签选择器是按钮组**：如果标签很多会占满表单区域。建议改为可搜索的下拉选择器或标签输入框。

### 3.4 a11y 问题

- 取消确认弹窗没有 `role="alertdialog"`、`aria-modal`、`aria-labelledby`，只有视觉样式。
- 封面图删除按钮 `X` 没有 `aria-label`。
- 地点搜索结果列表没有 `role="listbox"` 和键盘导航。

## 四、发布故事页 `/discover/create` 问题

- **与编辑页样式不一致**：发布页部分使用 DS token（`bg-background`、`border-border`、`bg-primary`），部分使用 amber 自定义样式，需要统一。
- **表单验证时机**：提交时才验证，用户填完一个字段后没有即时反馈。建议 onBlur 验证。
- **封面图是必填项**：`validate()` 中 `coverImage` 必填，但故事不一定需要封面。建议改为可选，或提供默认封面。
- **标签必须至少一个**：`tags.length === 0` 时报错，但用户可能不想打标签。建议改为可选。

---

## 五、跨页面共性问题

1. **三个页面三种视觉**：详情页 DS v2.0、编辑页旧琥珀渐变、发布页混合。需要统一到一个设计系统。
2. **字体权重混乱**：详情页标题 `font-bold`，编辑页标题 `font-semibold`，发布页标题 `font-semibold`，DS 应该有明确层级。
3. **圆角不一致**：`rounded-lg` / `rounded-xl` / `rounded-full` 混用，需要统一。
4. **i18n 不完全**：部分文案硬编码中文（如「有未保存的修改」「检测到未保存的草稿」），没有走 `useI18n`。
5. **移动端适配**：编辑页和发布页的复杂表单在移动端可用性差，需要专门优化。

## 六、优化建议优先级

### P0（立即做）

1. **统一编辑页到 DS v2.0**：去掉 amber 渐变背景、rounded-xl、自定义 amber 按钮，全部换成 DS token。
2. **统一三个页面的设计语言**：详情页、编辑页、发布页使用同一套颜色、圆角、按钮、输入框。
3. **补全编辑页 a11y**：弹窗加 `role="alertdialog"`、`aria-modal`、焦点管理。

### P1（下一轮迭代）

4. **优化详情页信息层级**：减少 byline metrics，突出作者和日期；调整标题和摘要样式。
5. **优化编辑页移动端**：基本信息可折叠，编辑器优先。
6. **统一圆角和字体权重**：建立明确的 type scale 和 radius scale。
7. **发布页与编辑页共用表单组件**：避免两套表单逻辑。

### P2（后续）

8. **SSR 详情页核心内容**：无 JS 用户也能阅读故事。
9. **点赞入口前置**：byline 或浮动按钮。
10. **标签选择器改为搜索式**：支持大量标签。

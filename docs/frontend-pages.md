# GoMate 前端页面与运行时

当前产品围绕“发现地点 → 创建或直接加入队伍 → 完成活动”。Astro SSR 与 React islands 和 Hono API 运行在同一 Worker。实际页面入口以 [pages](../src/pages/) 为准。

## 页面范围

| 领域       | 入口                                                                          | 职责                                                       |
| ---------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 首页       | `/`                                                                           | 公共地点地图、出发队伍和发现入口；登录前后共用核心发现流程 |
| 地点       | `/locations`、`/locations/[id]`                                               | 城市与兴趣筛选、详情、关联队伍                             |
| 队伍       | `/teams`、`/teams/[id]`、`/teams/create`、`/teams/[id]/edit`                  | 创建、直接加入、退出、必要成员管理、时间地点与集合信息     |
| 账号       | `/login`、`/register`、`/verify-email`、`/forgot-password`、`/reset-password` | 同源认证、邮件挑战                                         |
| 用户       | `/my-teams`、`/profile`、`/profile/edit`、`/users/[id]`                       | 队伍与必要个人资料                                         |
| 后台       | `/admin/*`                                                                    | 地点、标签、角色管理与只读队伍查询                         |
| 反馈与说明 | `/feedback`、`/about`、`/help`、`/privacy`、`/terms`                          | 一个反馈表单与产品/法律说明                                |
| 内容       | `/blog`、`/blog/[slug]`                                                       | 静态内容集合，不是用户故事发布                             |

故事、收藏、聊天、分享海报、个性化推荐、复杂行动本及申请审批入口已移除；旧路径不提供功能兼容。后台也不保留这些功能的管理入口。

地点与队伍详情的 Open Graph 图片复用地点公开封面；没有封面时省略图片元数据，不再引用已删除的分享海报 API，也不声明未经确认的图片尺寸。

## 地点发现

- 首页 Hero 右侧提供全国随机探索，用户点击抽选后居中揭晓；下方继续保留出发队伍看板与地图。照片墙使用首页加载的最多 6 张地点封面作装饰，不代表抽样范围。
- `GET /api/locations/random` 从全部 published 且属于启用 city 的地点抽取；不要求封面或坐标，不按城市、热度加权。单条 SQL 为各候选生成 SQLite `random()` 排序值并取第一条，近期记录按优先级排后；同一查询返回公开地点总数，避免计数与抽样分离的竞争窗口。它需要扫描候选集，不声称常数复杂度，也未进行生产规模压测。参考 [SQLite random()](https://www.sqlite.org/lang_corefunc.html#random)。
- `recent` 接受最多 10 个唯一 ID，逗号分隔、从最早到最近排列；有未近期抽中的地点时等概率抽取，否则选择最早的仍可公开访问的记录。当前标签页会话通过 sessionStorage 保存最近结果，存储不可用时退化为组件内存。该记录不用于认证或个性化推荐。
- 随机响应（含错误）禁止缓存；无候选时返回 `location: null, total: 0`，只有一个地点时提示。SSR 阶段按钮禁用，交互脚本完成 hydration 后才启用；每次只接受一个请求，8 秒超时且不自动重试；失败保留上次结果并提供重试。响应成功后立即揭晓，不人为延长等待；减少动态效果及运行中切换偏好均生效。
- 抽中地点展示名称、城市与封面，封面缺失或失败时使用占位；“查看地点”进入详情，“再选一个”留在首页。键盘焦点保持在触发按钮，不自动跳转；小屏精简照片墙，动效不依赖退出完成回调清理节点。

- 首页地图保留全国 → 省份两层视图、带封面缩略图的地点内嵌预览和原生详情链接；封面复用统计响应，失败回退到固定尺寸装饰占位。URL 的 `mapProvince` / `mapLocation` 保存选择；进入省份 push，连续选点 replace，保留其他参数。
- 返回地点详情前的页面时恢复选择及滚动位置；失效地点清除 ID 并提示，用户操作终止自动位置恢复。地图键盘焦点与 reduced-motion 行为按 [设计系统](design-system.md) 验证。
- 地点列表城市单选、兴趣多选；标签之间 OR，维度之间 AND。切换城市保留兴趣。热门城市来自启用服务的 city Region 的 `isHot` / `sortOrder`，非热门已选城市追加显示。
- 筛选更新期间保留已有结果和位置；旧请求不能覆盖新选择，失败提供重试。搜索有防抖；筛选条件与 cursor 窗口恢复使用现有 URL/history 合同。
- 详情只使用全局 Location ID；显示地点基本信息与关联队伍，没有收藏、故事回顾和海报请求。
- 详情采用地点优先的旅行手记布局，桌面首屏图文并排，手机单列且组队操作持续可达。介绍超过四行可展开，地址支持导航与复制状态反馈；无坐标时保留地址并隐藏导航。
- 关联队伍独立加载最多 3 条招募中队伍，提供完整列表入口；不把分页结果数量展示为总数。加载中、请求失败和真正空态分开呈现；地点与队伍请求均有 15 秒超时，手动重试不自动循环，切换地点或卸载取消旧请求。其他地点加载失败时隐藏该辅助区域。
- 地点详情封面使用 3:2 相纸叠卡：拖动或前后按钮循环切换，卡片倾斜甩出、下一张补位；不自动播放，显示当前张数。点击查看大图，短拖动回弹且不会误开大图。支持方向键、触屏纵向滚动和 reduced-motion；单张隐藏切换控件，图片去重，空相册显示占位。

- 地图 SVG 与 HTML 点位由同一个 Motion 进度同帧更新，360ms 平稳过渡，可从中途位置转向最新选择。
- 封面切图先解码，成功后由 Motion 变换驱动甩出和补位，失败保留当前照片并允许重试；新操作取消旧请求，15 秒超时。减少动态效果时直接切换，不旋转或弹跳。封面舞台、文字、边框和按钮复用系统语义颜色，适配浅色与深色主题。图片首次显示沿用轻微淡入，历史返回不重播首次入场。大图切图交叉淡化，保留旧图直到最新请求成功；15 秒超时或失败提供手动重试。
- 动效响应系统 reduced-motion 的即时切换。大图沿用共享 Modal 的焦点限制、背景 inert、滚动锁定和关闭后焦点恢复。

## 队伍与账号

- 创建/编辑使用共享活动类型枚举，地点支持的类型用于排序推荐而不创建另一套枚举。人数、满员判断包含队长。
- 创建/编辑队伍在 `components/features/teams/form/` 共用字段组件与请求数据转换，各自 hook 管理加载、校验和提交。创建保留地点选择与多行要求输入；编辑锁定地点和日期，人数不得低于已报名人数，逐条要求最多十条。时长选项及空白处理沿用各入口规则，不通过统一模式开关抹平差异。
- 加入直接调用成员接口，不再展示申请理由、审批等待或审批通知。活动开始前可退出，队长可移除成员；活动状态约束由 API 决定。
- 集合信息并入队伍；队伍详情以出发邀请卡集中日期、地点、人数和身份操作。队员/队长优先看到集合信息，完整介绍移至正文，成员显示昵称并支持展开。桌面与手机各保留一个可见的主要加入入口，手机底栏按实际高度及 safe area 留白，不遮挡内容或键盘焦点。
- “我的队伍”保留创建、加入及历史视图，不请求待审批列表。角色和状态使用共享枚举翻译。
- 账号页面保留登录、邮箱验证、密码重置、头像及必要资料。Google 按钮仅在运行时配置完整时显示；回跳地址限同源安全路径。

## 个人菜单

公共导航的管理员入口统一收纳到个人选项：个人资料、我的队伍、分隔线、管理后台、快速添加地点、分隔线、退出登录。管理员分组仅在当前会话角色为 admin 时显示；访客和普通用户不可见。桌面使用头像下拉菜单，手机使用导航抽屉中的个人区域，发布队伍保持独立操作。

快速添加地点继续使用草稿表单。打开时关闭个人菜单，弹窗独立挂载；关闭后焦点回到桌面头像或手机菜单按钮。入口隐藏不替代后台 SSR 和 API 的权限校验。

## 后台边界

Astro middleware 在 SSR 前鉴权：访客前往登录页，普通用户得到 403，管理员页面 `private, no-store`。后台使用独立壳层，宽屏侧栏、小屏抽屉；内部导航保留支持的语言前缀。

地点管理可搜索、草稿/发布/归档、编辑图片与标签；标签引用计数只包含地点和队伍。用户角色变更禁止修改自己或撤销最后一位管理员。队伍后台只读，招募状态与生命周期分开筛选，不提供管理写操作。

地点编辑器在 `components/features/location-form/` 中分离表单投影与保存状态规则（`location-form-data.ts`）、浏览器恢复草稿（`location-form-draft.ts`）和 API/React 状态编排（`use-location-form.ts`）。恢复草稿沿用创建/各地点隔离的键、七天有效期与 v2 → v3 规范化；迁移不延长过期时间。浏览器存储被禁用或额度耗尽时仍可加载和保存到 API，但不保证本地恢复副本可写入或清除；已成功的 API 保存不会因清除草稿失败而显示失败。

## 双语与渲染

只支持 `zh-CN` 和 `en`。语言选项、SSR、邮件及 API 参数使用共享 locale 合同；移除日语选项和专属逻辑，不为旧日语路径、Cookie 或参数增加迁移规则。用户自行录入的文本不做语言删除。

SSR 声明 namespace；公开浏览页面通过每个请求独立的 `I18nSnapshot` 提供正文翻译，SSR 与 hydration 首帧一致，其他 island 仍可消费页面注入缓存。不得以模块级可变 locale 共享不同请求的语言。纯展示由 Astro 承载，需要状态的交互才使用 React island。可见提示、错误和可访问名称都走 i18n。

反馈表单仅保留邮箱和内容，失败保留输入，提交中禁用重复操作，成功/失败使用辅助技术可感知状态。服务端错误不直接作为未翻译文案展示。

## 验证

使用实际 Worker/浏览器验证首页、地点、创建/直接加入/退出、活动状态和中英文；同时覆盖匿名保护、过期请求、窄屏、键盘焦点及 reduced-motion。不存在用户使用数据时，不将“删除了复杂功能”表述为已经证明转化率提升。

## 页面和请求边界

- `Layout.astro` 负责文档骨架；静态 SEO 使用显式 `titleKey`/`descriptionKey`，动态用户文本使用 `title`/`description`。`page-metadata.ts` 统一默认文案和动态标题后缀，不按中文展示字符串反向查翻译。
- 主题首屏初始化与路由预加载分别由 `ThemeInit.astro`、`RoutePrefetch.astro` 承载；主题 class 只放在根 html，避免 body 保留旧暗色状态。预加载只响应鼠标停留或键盘焦点表达的意图，最多 8 个公共网址；省流量与慢速网络跳过，不在空闲时自动请求列表。
- 队伍列表 SSR 与客户端共用 URL 筛选解析及 API 参数转换；请求取消、加载与分页状态由各运行时管理。建队地点详情和队伍标签加载失败提供独立重试入口，过期响应不能覆盖新选择。
- 外部 JSON 响应在消费边界显式声明共享 DTO 或解析为 unknown；不通过全局 `Body.json()` 的 any 重载放宽全部请求。类型声明不替代运行时校验。


## 首屏与刷新行为

- 首页、地点与队伍列表/详情消费服务端翻译快照；地点、队伍详情复用 SSR 已读取的 DTO，首次激活不重复读取正文。队伍身份与成员状态独立查询后才开放操作；加入、退出、成团后仍以 API 响应刷新。
- 详情 SSR 沿用 API 的访问者权限裁剪，并设置 `private, no-store`；不得把成员联系方式缓存给其他访问者。SSR 读取失败仍由客户端请求与重试恢复，目前 `serverApiGet` 将非成功结果归为 null，并未提供精确的 SSR 404/503 分类。
- 隐私与条款正文只在服务端渲染，导航与页脚保留各自交互。管理员快捷表单按打开意图加载，加载完成后聚焦首个输入。
- 地点卡片使用原生 lazy 图片，首屏指定 eager/high 优先级；详情首图直接输出且不在 hydration 后替换节点。后续相册切换保留旧图直到新图解码成功。
- 地点与队伍列表保留刷新中的旧内容，明确更新/失败状态；筛选立即取消旧请求，防抖期间也不接受旧结果。队伍游标进入 URL，历史记录保留当前页、已知游标与滚动位置。
- 后台用户、地点列表刷新时保留内容，取消旧请求并只接受最新结果；查询有 15 秒预算，失败可重新提交筛选。后台队伍列表沿用已有取消与重试流程。
- 性能测量口径和全系统检查入口见[性能验收](performance.md)。

队伍列表卡片和详情的出发时间使用地点所属地区的 IANA 时区，缺失时固定回退到 UTC；服务端与浏览器不再分别使用运行环境的默认时区。首页继续先保持 SSR 时区、接管后显示访客本地时间。

公开地点/队伍列表的筛选与分页控件在 React 接管前保持禁用，避免首屏内容已出现但事件尚未绑定时丢失输入；原生详情链接可直接导航。

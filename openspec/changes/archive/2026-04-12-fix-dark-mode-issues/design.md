## Context

通过代码审查发现以下暗黑模式问题：

1. **导航栏 (navbar.tsx)**：
   - 使用硬编码颜色如 `text-[#8f7f6e]`, `hover:text-[#1e1812]`, `hover:bg-[#FFFBEB]`
   - 移动端抽屉使用固定白色背景 `background: "rgba(255,255,255,0.97)"`
   - 下拉菜单背景、边框颜色未适配暗黑模式

2. **主题切换 (theme-toggle.tsx)**：
   - 自定义下拉菜单使用硬编码浅色背景
   - 菜单项 hover 状态颜色固定

3. **页脚 (footer.tsx)**：
   - 部分元素使用固定颜色

**修复策略**：
- 优先使用 Tailwind 的 `dark:` 变体类名
- 对于内联样式，使用 CSS 变量或条件渲染
- 保持与现有 design system 一致

## Goals / Non-Goals

**Goals:**
- 导航栏在暗黑模式下正确显示（桌面端+移动端）
- 主题切换下拉菜单在暗黑模式下可读
- 页脚在暗黑模式下正确渲染
- 所有修复保持原有设计意图

**Non-Goals:**
- 不修改功能逻辑
- 不引入新的依赖
- 不重新设计组件

## Decisions

### 1. 修复方式：Tailwind dark: 变体优先
**选择**：使用 `dark:bg-`, `dark:text-`, `dark:border-` 等变体

**理由**：
- 与 Tailwind CSS 配置兼容
- 代码可读性好
- 无需运行时 JavaScript

### 2. 特殊元素处理：CSS 变量
**选择**：对于复杂颜色（如半透明背景），使用 CSS 变量

**理由**：
- 需要同时切换背景和边框
- 保持与 globals.css 中定义的颜色系统一致

### 3. 移动端菜单策略
**选择**：为移动端抽屉添加完整的 `.dark` 样式覆盖

**理由**：
- 移动端菜单是独立组件
- 需要完全不同的颜色方案

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| **过度修复**：修改太多地方引入新问题 | 逐个组件修复，每次验证 |
| **颜色不一致**：修复后颜色可能与 design system 不符 | 参考 globals.css 中的 CSS 变量 |
| **移动端遗漏**：桌面端修复但移动端遗漏 | 明确检查移动端代码路径 |

## Migration Plan
